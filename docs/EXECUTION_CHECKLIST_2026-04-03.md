# 실행 체크리스트

기준 날짜: 2026-04-03

이 문서는 현재 `auto_coin_bot` 프로젝트를 기준으로, 앞으로 무엇을 어떤 순서로 실행하면 되는지 `체크리스트` 형태로 정리한 문서입니다.

원칙

- 단기: 운영 안정화와 비교 가능성 확보
- 중기: 구조 레이어 추가와 전략 엔진 정리
- 장기: ML, 고급 리플레이, 보안/실험 관리 고도화

---

## 1. 단기 체크리스트

### 1-1. [P0] 전략 세트 파일화

목표

- `.env` 직접 수정 의존도를 줄이고, 보수형/중간형/혼합형 세트를 파일 단위로 관리

할 일

- [ ] `config/sets/` 또는 `env_overrides/` 아래 세트 파일 정리
- [ ] 각 세트 파일에 적용 목적과 날짜 표기
- [ ] 현재 적용 세트와 기준선 스냅샷 경로를 문서에 연결

완료 기준

- 보수형/중간형/혼합형 세트 파일이 각각 존재
- `.env` 에 어떤 세트를 반영했는지 사람이 바로 알 수 있음
- 현재 기준 파일은 날짜 없는 canonical 이름으로 존재
- 과거 이력 파일은 `env_overrides/history/` 에 보관

확인 방법

- `env_overrides/` 목록 확인
- `docs/STRATEGY_DECISIONS.md` 또는 세트 문서에서 적용 이력 확인

### 1-2. [P0] 실험 결과 레지스트리 추가

목표

- `reports/backtest_batches/` 결과를 한 번에 찾을 수 있는 인덱스 파일 구축

할 일

- [ ] `reports/backtest_registry.json` 파일 생성 도구 추가
- [ ] 항목에 아래 필드 포함
  - `label`
  - `created_at`
  - `before_dir`
  - `after_dir`
  - `symbols`
  - `summary_path`
  - `diff_path`
- [ ] 새 batch/diff 생성 시 레지스트리 자동 갱신

완료 기준

확인 방법

- `reports/backtest_registry.json` 열어 최근 실행 3건 확인

### 1-3. [P1] 백테스트-실거래 차이 자동 코멘트 보강

목표

- 단순 수치 비교를 넘어서, 왜 차이가 나는지 자동 설명 강화

할 일

- [ ] `holding_seconds` 차이 코멘트 보강
- [ ] `profit_protect`, `stop_loss`, `partial_stop_loss` 비중 변화 코멘트 추가
- [ ] `MFE 대비 실현 비율` 차이 코멘트 추가
- [ ] 실거래 체결 품질(`fill_ratio`, `slippage`) 연관 코멘트 추가

완료 기준

- `comparison.md` 를 읽으면 “어디가 달라졌는지”와 “무엇을 의심해야 하는지”가 바로 보임

확인 방법

- 최근 `comparison.md` 3개 확인
- 코멘트가 수치 나열이 아니라 원인 추정으로 읽히는지 점검

### 1-4. [P1] OKX 데이터 계층 강화

목표

- 업비트 대비 OKX 데이터 질/지연 차이를 줄여 비교 공정성 확보

할 일

- [ ] OKX도 가능 범위에서 실시간 시장 상태 수집 구조 검토
- [ ] REST fallback 최소화 가능 지점 정리
- [ ] 실제 지연/오류 패턴 로그화

완료 기준

- OKX와 업비트 모두 데이터 수집 품질을 로그 기준으로 비교 가능

확인 방법

- `api_latency_ms`, 수집 실패율, fallback 빈도 집계

### 1-5. [P1] 시장 구조 / 미시구조 shadow mode 준비

목표

- 실제 차단 전에 “차단했더라면 어땠는지” 로그만 남기는 준비

할 일

- [ ] reason code 목록 확정
- [ ] `market_structure`, `microstructure` stage 설계 확정
- [ ] 차단 없이 로그만 남기는 shadow mode 플래그 설계

완료 기준

- 아직 거래는 막지 않지만, 로그에 새 stage 가 찍힘

확인 방법

- `strategy.jsonl` 에 새 stage 발생 여부 확인

## 4. 실행 우선순위

지금 가장 현실적인 순서

1. `[P0]` 전략 세트 파일화
2. `[P0]` 실험 결과 레지스트리
3. `[P1]` 시장 구조 shadow mode
4. `[P1]` 오더북 미시구조 shadow mode
5. `[P1]` 전략 엔진 계층 분리
6. `[P0]` 실험 자동화 도구
7. `[P2]` ML 메타 필터

## 5. 운영 메모

- 현재 단계에서는 `기능을 더 붙이는 것`보다 `구조를 더 명확히 하는 것`이 우선입니다.
- 특히 새로운 필터는 바로 실차단하지 말고 shadow mode 로 먼저 검증해야 합니다.
- 지금 봇은 이미 충분히 복잡하므로, 다음 성공 포인트는 전략 복잡도 증가보다 `실험 관리`, `설정 관리`, `데이터 품질 관리`에 있습니다.
